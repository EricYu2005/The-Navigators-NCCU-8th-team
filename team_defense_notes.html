1 保健食品綜合效益評分 (Value Score) 機制

Q1：保健品的「綜合效益評分 (80~95分)」是怎麼算出來的？背後科學與商業依據是什麼？

我們的模型並非憑空主觀給分，而是根據食品科學實證與每日真實性價比所建立的多因子加權演算法：

評分維度 權重 評估標準與科學依據
1. 有效成分足量度 40% 比對國際臨床試驗與衛福部每日建議攝取量。例如：魚油單日 Omega-3 是否達到 1000mg 以上（低劑量扣分）；葉黃素是否符合 AREDS-2 專利黃金比例 10mg:2mg。
2. 劑型與專利吸收率 25% 生物利用率高者給予加分。例如：魚油 rTG 型（高吸收）> TG 型 > EE 型；葉黃素游離型 (FloraGLO) > 傳統酯化型；鈣劑檸檬酸鈣/海藻鈣 > 碳酸鈣。
3. 每日真實花費性價比 25% 打破「單盒大包裝便宜」的行銷幻覺，計算「每毫克有效成分的每日實際花費」。每日平均花費落在主流合理區間（例如高濃度魚油 $30~$45/天）給予滿分，過度溢價品牌扣分。
4. 純淨度與少添加 10% 無多餘人工色素、無多餘糖分與香料（例如許多市售兒童或女性益生菌添加高達 40% 糖粉，此項目會被扣分）。
口試標準應對話術：
「報告評審，市面上的保健品評測大多只看單盒售價或品牌知名度。好選保健的評分核心是『有效濃度 ÷ 每日真實花費』，結合劑型吸收專利與無糖純淨度，幫消費者撕下廣告話術，找出單位效益最高的選擇。」
Q2：為什麼首頁「尋找比價庫」去掉了綜合評分，但在「有興趣清單」裡卻保留？

這是有意為之的「第三方中立性原則 (Platform Neutrality)」：

  • 公開比價庫（公域貨架）保持中立： 如果在公開搜尋目錄上直接標示誰 95 分、誰 80 分，平台很容易被消費者與廠商質疑「球員兼裁判」、「是否收了高分品牌的廣告置入費用」。因此貨架上只揭露客觀事實（成分規格、每日費用、真實優缺點）。
  • 有興趣清單（個人決策空間）提供決策輔助： 當使用者將 2~3 款心儀商品放進自己的清單時，評分轉化為個人化比對的決策參考指標，協助消費者在預算內做出理性取捨。

Q2：為什麼平台目前不向使用者真的收錢？這在創業 MVP 計畫中代表什麼？

這是精實創業（Lean Startup）的核心方法論：付費意願假說驗證（Willingness-to-Pay Validation）。

  • 過早串接金流是創業常見陷阱： 在產品知名度未建立前，要求消費者輸入信用卡，會造成 90% 以上的非理性跳出（Drop-off），導致團隊無法區分究竟是「產品沒價值」還是「單純結帳麻煩」。
  • 以「留名單與使用回饋」驗證真實意願： 我們在用戶遇到 Pro 去冗或狀態日誌門檻時，引導其留下稱呼、信箱並為流程順暢度評分 (1~5分) 以免費開通體驗。若消費者願意留下真實私人電子郵件與回饋換取服務，這就是最強有力的「高價值付費潛力（High Purchase Intent）」證明！
  • Demo 演示操作： 專題展示時，組員可先展示免費版的上鎖門檻，點擊留名單送出後，系統瞬間解鎖 Pro 權限，向評審證明轉換漏斗的完整性。

3 留名單機制、資安隱私與如何查看名單

Q1：留名單的具體流程是什麼？

我們的留名單流程設計追求「極致零摩擦」：

  1. 觸發點與 LINE 實名認證門檻： 使用者在去冗分析頁點「解鎖 Pro」、在日曆點「解鎖日誌」、或在方案彈窗點「登記回饋開通」時，系統強制檢驗 LINE 實名登入狀態；未登入者必須透過官方 LINE OAuth 登入以杜絕匿名洗榜與組員自我灌水。
  2. 自動預填與簡短問卷： 已登入 LINE 的使用者，系統會自動帶入 LINE 實名稱呼；問卷僅需確認稱呼、年齡、電子信箱、評選流程順暢度（1~5 分）及選填使用回饋建議，使用者只需 5 秒即可完成，完全留在站內無外部跳轉！
  3. 存入資料庫並即刻開通： 點擊「送出回饋」後，資料透過 API 寫入後台 SQLite 資料庫的 leads 表並綁定 LINE UID，前端立即將用戶提升為 Pro 權限並解除所有去冗精算遮罩與身體動態日誌！
Q2：為什麼網頁前台沒有「查看名單」的按鈕？

個資保護原則（Privacy by Design）： 留名單包含真實消費者的稱呼、電子信箱與回饋意見，這屬於敏感個人資料。若在前台網頁放一個按鈕讓任何人都能點開看，會嚴重違反資安常理與個人資料保護精神。因此前台絕對不對外公開名單。

Q3：團隊自己要看收集到的名單，該如何操作？

團隊備有專屬管理通道，操作極為簡便：

名單匯出三步驟：
1. 在專案資料夾中雙擊執行 sync.cmd。
2. 在主選單中輸入號碼 7（匯出名單為 Excel 試算表檔案）。
3. 系統會自動生成帶有 UTF-8 BOM 的標準 Excel 檔案（PurePick_消費者登記名單_YYYY-MM-DD.csv），並自動為您在 Excel 中彈出開啟，繁體中文 100% 絕無亂碼！

匯出的 Excel 欄位完整包含：登記序號、登記時間、消費者稱呼、LINE實名驗證UID、年齡、電子信箱、流程順暢度評分 (1~5分)、來源管道標籤、使用體驗回饋建議。

Q4：評審質疑名單會不會是你們組員自己隨便在網頁上填寫灌水的？
回答關鍵：
「報告評審，我們在系統底層架構上設計了 LINE 官方 OAuth 2.0 實名認證門檻。所有留下名單與解鎖 Pro 的受測者，後台 API 強制驗證其真實 LINE User ID（UID）與實名授權。前端未登入 LINE 者無法送出名單；後台資料庫與匯出的 Excel 表格中均詳實記錄了對應的真實 LINE UID。這從技術層面徹底杜絕匿名刷榜與組員自我灌水作弊，保證名單 100% 來自真實獨立使用者！」

4 評審常見挑戰問題應答守則 (Cheat Sheet)

Q1：你們做保健品比較與日曆，會不會有《醫療法》或違法宣稱療效的法律風險？
回答關鍵：
「報告評審，我們非常重視合規性。首先，本平台在頁尾有嚴格的學術免責聲明：『本網頁僅供政治大學創創入門課程使用，非正式平台』。其次，我們不做任何臨床疾病診斷或治療處方，我們的定位是『生活消費決策輔助軟體』，所有劑量標準均嚴格引述衛生福利部國民健康署公告之『國人膳食營養素參考攝取量 (DRIs)』與安全上限 (UL)，主打幫消費者『去冗防浪費』而非宣稱療效。」
Q2：市面上已經有 iHerb、屈臣氏、康是美，甚至 Dcard 推薦文，為什麼還需要好選保健？
回答關鍵：
「報告評審，核心差異在於商業利益的對立面：
• 通路商（iHerb、屈臣氏）與網紅推薦：他們的獲利來自『銷售抽成』，誘因永遠是說服消費者越買越多、買更高單價的商品。
• 好選保健：我們的商業模式是『獨立消費者訂閱』，我們的算法誘因是『幫消費者砍掉重複買的多餘產品』。只要幫用戶省下重複買的一瓶魚油或維他命（省 $1,000+），就遠遠超過訂閱費，我們是站在消費者同一陣線的把關者。」
Q3：LINE 官方帳號設定必須填寫地址，團隊填在政大，是否會引發合規或欺瞞疑慮？
回答關鍵（營運模式與誠實揭露原則）：
「報告評審，LINE 官方帳號在建立時系統強制要求填寫聯絡地址。PurePick 是國立政治大學創創入門課程團隊所研發的學術專案，因此以專案發源基地（國立政治大學）作為聯絡申報。
更重要的是，我們秉持極致資訊對稱原則：在網站 Footer、使用說明與 LINE 官方帳號簡介中皆已同步明確載明：『本專案為政大創創入門課程專題成果，採全線上運作無實體門市，所填地址僅供平台系統驗證與學術聯絡使用』，充分揭露無實體營運據點，完全合乎消費者保護與平台合規告知精神！」
Q4：這本質上是個展示型專案、無法做正式商業廣告行銷，你們如何有效證明這不是自嗨，而是有真實市場需求？

這正是精實創業（Lean Startup）的核心精髓：「在零廣告預算下，以最短時間驗證真實付費意願與痛點真偽」。

5 未來概念展望：隨身感測智慧藥盒 (IoT Pillbox 願景)

Q1：期末報告最後一頁的「未來展望」，為什麼提出「智慧藥盒」概念？

這純粹是團隊針對消費者長期痛點所提出的「遠期產品願景（Visionary Concept）」，目前不涉及硬體報價與量產，用以向評審展示團隊對未來生態系的想像力：

  • 純軟體解決認知，輕便智慧藥盒解決「無感自動紀錄」： 純軟體幫消費者抓出重複買、省下冤枉錢；但在日常外出執行上，忘記吃或忘記手動打開手機打卡仍是最大阻力。
  • 產品概念發想： 構想一款輕便隨身藥盒，每天出門前先將當天要吃的跨品牌保健品分裝進去；每個欄位內建高靈敏度微重量感測器（Micro-weight Sensor），取出服用即自動偵測重量變化並記錄，回家只要與手機連線、什麼都不用按就自動同步更新服用日曆；盒蓋並可結合微型電動馬達實現緩啟緩閉，賦予日常吃保健品的尊榮儀式感。
  • 明確不做每日藥袋： 市面上已有現成藥袋分裝服務，且賣單一品牌藥袋會破壞第三方中立性。若未來延伸硬體，跨品牌適用的輕便感測藥盒才是兼顧中立與長遠價值的方向。
口試標準應對話術（輕鬆回答、不畫大餅）：
「報告評審，智慧藥盒純粹是我們在期末簡報中提出的遠期願景發想（Concept Vision）。我們現階段 100% 專注在 Phase 1 的軟體實作與封測驗證；提出輕便微重量感測藥盒是想表達，未來生態系成熟時，能透過『取出即自動感測、回家自動同步』徹底消滅手動打卡摩擦，讓 PurePick 的跨品牌健康管理閉環更完整。」

場景三：年度健檢數值自動連動

公司健檢肝腎血脂指數反饋

健康存摺亦同步收錄抽血報告（GOT/GPT、肌酸酐、血脂、空腹血糖）。當白領做完年度公司健檢發現血脂偏高或腎絲球過濾率異常時，系統自動調整 Portfolio 推薦與安全上限警示。

10 智能用藥提醒與 LINE 官方帳號時段推播架構 (非騷擾式推播)

Q1：市面上許多吃藥提醒 App 最後都被使用者刪除或關閉通知，PurePick 的 LINE 推播有何本質差別？

傳統用藥提醒失敗的三大主因是：「必須額外下載不常用的 App」、「無差別定時響鬧造成干擾」以及「時段混亂缺乏邏輯」。PurePick 從第一天起就顛覆此設計：

  • 零下載摩擦（原生 LINE 官方帳號）： 台灣民眾每日開啟 LINE 頻率最高，我們直接透過 LINE 官方帳號推播，使用者無須在手機額外下載專用 App 即可接收訊息。
  • 分時段智能精準推播（按成分特性提醒）： 每款保健品本來就有適合的服用時段。早晨 7:00 僅推播適合早餐前/後服用的品項（如 B 群、魚油、維生素 C）；午間 11:50 提醒午餐時段品項；夜間 21:30 才推播睡前品項（如鈣片、鎂、睡眠益生菌）。絕不在早上七點無效打擾睡前要吃的商品，真正做到「在對的時間提醒對的事」。
  • 即時動態連動： 使用者在日曆開啟「生病休養暫停」或完成打卡後，系統自動智慧靜音對應時段的提醒，避免多重訊息打擾。
Q2：這套 LINE 提醒背後的技術架構如何以極致精實成本（Lean Cost）實現？

新創團隊不應在前期耗費預算維護昂貴的 24 小時長駐雲端主機。我們設計了「Serverless 雲端排程自動化架構」：

  • LINE Messaging API： 透過 PurePick 官方帳號 Push Message 管道，將客製化健康提醒與每日看診大字卡精準送達受測者手機。
  • GitHub Actions 定時觸發排程： 運用 GitHub 提供的免費 CI/CD Cron 資源（.github/workflows/line-reminder.yml），在設定時段自動喚醒檢驗腳本，運算當前時段需提醒的用戶與保健食品清單並觸發推播，執行完畢即刻釋放資源。
  • 極致精實維運成本： GitHub Actions 排程本身完全免費（$0）；平時開發可跑在免費方案，封測與期末發表期間則升級 1 個月 Render Starter（$7 美金／約 NT$ 225 元/月）確保 24 小時常駐不休眠、手機與評審掃碼秒開且後台資料庫不因休眠重置，展現對工程成本與穩定度平衡的架構能力。

  • 2. 對比「StackSnap」— 歐美英文 App vs. 台灣本土資料庫與 LINE 零下載生態： StackSnap 是最接近 PurePick 的國外同類掃描去冗 App，但存在三大水土不服：(a) 綁定美國 NIH DSLD 資料庫與英文介面，台灣大宗本土品牌（大研、營養師輕食、悠活原力、VITABOX、娘家）與日本藥妝查不到，也不符合台灣衛福部 DRIs 第八版標準；(b) 獨立英文 App 對台灣 35～60 歲族群下載與通知門檻高，而 PurePick 採 免下載 PWA ＋ LINE 官方帳號分時段推播 ＋ 一鍵 LINE 分享看診卡；(c) StackSnap 偏重「買後盤點」，PurePick 往前延伸到「買前跨品牌透明比價與去冗試算」。
