1 保健食品綜合效益評分 (Value Score) 機制

Q1：保健品的「綜合效益評分 (80~95分)」是怎麼算出來的？背後科學與商業依據是什麼？

我們的模型並非憑空主觀給分，而是根據食品科學實證與每日真實性價比所建立的多因子加權演算法：

評分維度 權重 評估標準與科學依據
1. 有效成分足量度 40% 比對國際臨床試驗與衛福部每日建議攝取量。例如：魚油單日 Omega-3 是否達到 1000mg 以上（低劑量扣分）；葉黃素是否符合 AREDS-2 專利黃金比例 10mg:2mg。
2. 劑型與專利吸收率 25% 生物利用率高者給予加分。例如：魚油 rTG 型（高吸收）> TG 型 > EE 型；葉黃素游離型 (FloraGLO) > 傳統酯化型；鈣劑檸檬酸鈣/海藻鈣 > 碳酸鈣。
3. 每日真實花費性價比 25% 打破「單盒大包裝便宜」的行銷幻覺，計算「每毫克有效成分的每日實際花費」。每日平均花費落在主流合理區間（例如高濃度魚油 $30~$45/天）給予滿分，過度溢價品牌扣分。
4. 純淨度與少添加 10% 無多餘人工色素、無多餘糖分與香料（例如許多市售兒童或女性益生菌添加高達 40% 糖粉，此項目會被扣分）。
口試標準應對話術：
「報告評審，市面上的保健品評測大多只看單盒售價或品牌知名度。好選保健的評分核心是『有效濃度 ÷ 每日真實花費』，結合劑型吸收專利與無糖純淨度，幫消費者撕下廣告話術，找出單位效益最高的選擇。」
Q2：為什麼首頁「尋找比價庫」去掉了綜合評分，但在「有興趣清單」裡卻保留？

這是有意為之的「第三方中立性原則 (Platform Neutrality)」：

  • 公開比價庫（公域貨架）保持中立： 如果在公開搜尋目錄上直接標示誰 95 分、誰 80 分，平台很容易被消費者與廠商質疑「球員兼裁判」、「是否收了高分品牌的廣告置入費用」。因此貨架上只揭露客觀事實（成分規格、每日費用、真實優缺點）。
  • 有興趣清單（個人決策空間）提供決策輔助： 當使用者將 2~3 款心儀商品放進自己的清單時，評分轉化為個人化比對的決策參考指標，協助消費者在預算內做出理性取捨。

Q2：為什麼平台目前不向使用者真的收錢？這在創業 MVP 計畫中代表什麼？

這是精實創業（Lean Startup）的核心方法論：付費意願假說驗證（Willingness-to-Pay Validation）。

  • 過早串接金流是創業常見陷阱： 在產品知名度未建立前，要求消費者輸入信用卡，會造成 90% 以上的非理性跳出（Drop-off），導致團隊無法區分究竟是「產品沒價值」還是「單純結帳麻煩」。
  • 以「留名單與使用回饋」驗證真實意願： 我們在用戶遇到 Pro 去冗或狀態日誌門檻時，引導其留下稱呼、信箱並為流程順暢度評分 (1~5分) 以免費開通體驗。若消費者願意留下真實私人電子郵件與回饋換取服務，這就是最強有力的「高價值付費潛力（High Purchase Intent）」證明！
  • Demo 演示操作： 專題展示時，組員可先展示免費版的上鎖門檻，點擊留名單送出後，系統瞬間解鎖 Pro 權限，向評審證明轉換漏斗的完整性。

3 留名單機制、資安隱私與如何查看名單

Q1：留名單的具體流程是什麼？

我們的留名單流程設計追求「極致零摩擦」：

  1. 觸發點與 LINE 實名認證門檻： 使用者在首頁點「索取報告」、在去冗頁點「解鎖 Pro」、在日曆點「解鎖日誌」、或在方案彈窗點「登記回饋開通」時，系統強制檢驗 LINE 實名登入狀態；未登入者必須透過官方 LINE OAuth 登入以杜絕匿名洗榜與組員自我灌水。
  2. 自動預填與簡短問卷： 已登入 LINE 的使用者，系統會自動帶入 LINE 實名稱呼；問卷僅需確認稱呼、年齡、電子信箱、評選流程順暢度（1~5 分）及選填諮詢問題，使用者只需 5 秒即可完成，完全留在站內無外部跳轉！
  3. 存入資料庫並即刻開通： 點擊「送出回饋」後，資料透過 API 寫入後台 SQLite 資料庫的 leads 表並綁定 LINE UID，前端立即將用戶提升為 Pro 權限並解除所有去冗精算遮罩與身體動態日誌！
Q2：為什麼網頁前台沒有「查看名單」的按鈕？

個資保護原則（Privacy by Design）： 留名單包含真實消費者的稱呼、電子信箱與健康困擾，這屬於敏感個人資料。若在前台網頁放一個按鈕讓任何人都能點開看，會嚴重違反資安常理與個人資料保護精神。因此前台絕對不對外公開名單。

Q3：團隊自己要看收集到的名單，該如何操作？

團隊備有專屬管理通道，操作極為簡便：

名單匯出三步驟：
1. 在專案資料夾中雙擊執行 sync.cmd。
2. 在主選單中輸入號碼 7（匯出名單為 Excel 試算表檔案）。
3. 系統會自動生成帶有 UTF-8 BOM 的標準 Excel 檔案（PurePick_消費者登記名單_YYYY-MM-DD.csv），並自動為您在 Excel 中彈出開啟，繁體中文 100% 絕無亂碼！

匯出的 Excel 欄位完整包含：登記序號、登記時間、消費者稱呼、LINE實名驗證UID、年齡、電子信箱、流程順暢度評分 (1~5分)、來源管道標籤、諮詢問題與回饋建議。

Q4：評審質疑名單會不會是你們組員自己隨便在網頁上填寫灌水的？
回答關鍵：
「報告評審，我們在系統底層架構上設計了 LINE 官方 OAuth 2.0 實名認證門檻。所有留下名單與解鎖 Pro 的受測者，後台 API 強制驗證其真實 LINE User ID（UID）與實名授權。前端未登入 LINE 者無法送出名單；後台資料庫與匯出的 Excel 表格中均詳實記錄了對應的真實 LINE UID。這從技術層面徹底杜絕匿名刷榜與組員自我灌水作弊，保證名單 100% 來自真實獨立使用者！」

4 評審常見挑戰問題應答守則 (Cheat Sheet)

Q1：你們做保健品比較與日曆，會不會有《醫療法》或違法宣稱療效的法律風險？
回答關鍵：
「報告評審，我們非常重視合規性。首先，本平台在頁尾有嚴格的學術免責聲明：『本網頁僅供政治大學創創入門課程使用，非正式平台』。其次，我們不做任何臨床疾病診斷或治療處方，我們的定位是『生活消費決策輔助軟體』，所有劑量標準均嚴格引述衛生福利部國民健康署公告之『國人膳食營養素參考攝取量 (DRIs)』與安全上限 (UL)，主打幫消費者『去冗防浪費』而非宣稱療效。」
Q2：市面上已經有 iHerb、屈臣氏、康是美，甚至 Dcard 推薦文，為什麼還需要好選保健？
回答關鍵：
「報告評審，核心差異在於商業利益的對立面：
• 通路商（iHerb、屈臣氏）與網紅推薦：他們的獲利來自『銷售抽成』，誘因永遠是說服消費者越買越多、買更高單價的商品。
• 好選保健：我們的商業模式是『獨立消費者訂閱』，我們的算法誘因是『幫消費者砍掉重複買的多餘產品』。只要幫用戶省下重複買的一瓶魚油或維他命（省 $1,000+），就遠遠超過訂閱費，我們是站在消費者同一陣線的把關者。」

5 方案二未來展望：軟硬整合智慧藥盒 (IoT Dispenser) 與每日隨身小撕包

Q1：為什麼在純軟體去冗之外，還要提出「智慧藥盒」與「隨身小撕包」作為長期護城河？

純軟體平台解決了「認知階段」的困擾（知道自己買錯、重複買），但在「日常落地執行」上，消費者仍面臨四大家常痛苦：

  • 瓶瓶罐罐佔桌面： 買了 4~6 罐不同廠牌的保健品，散落在餐桌、辦公桌，視覺雜亂且不易攜帶。
  • 忘記吃與重複吃： 常常忘了今天早上到底吃了沒，長輩尤其容易重複服用造成代謝過量。
  • 吃錯時段吸收折損： 鈣片與鐵劑混在一起吃相互競爭吸收通道；魚油（脂溶性）在空腹時吃吸收率大打折扣。
  • 受潮氧化發黑過期： 台灣潮濕氣候下，大瓶裝開開關關容易受潮變質，最後半罐往往直接丟棄浪費。

因此，「軟硬整合智慧藥盒」與「客製化每日隨身小撕包」是 PurePick 從決策工具邁向全生命週期健康管家的關鍵實體錨點。

Q2：三階段落地藍圖（3-Phase Roadmap）具體如何推進？

我們規劃了穩健的循序漸進藍圖：

Phase 1（當前成果）

手機版 Web App ＋ 告知醫生看診清單

• PurePick 跨品牌成分比對與去冗引擎
• 手機版 Web App（加到主畫面）與購物一鍵分享匯入

• 資本需求：低，專注驗證留名單與付費意願

Phase 2（未來展望第 1 年）

軟硬整合家用智慧藥盒 (IoT Dispenser)

• 6~8 槽模組化分格出藥機構，支援各式膠囊膜衣錠
• 燈號導引自動出藥（早晨綠燈、睡前藍燈一鍵吐藥）
• 藍牙 / Wi-Fi 同步用藥日誌，長輩漏吃主動推播 LINE
• 重力感測剩餘庫存，不足 5 日份自動提醒補貨

Phase 3（未來展望 2~3 年）

GMP 認證代工個人化每日小撕包

• 演算法依據健康數據輸出個人化配方（去瓶化）

• 每日一包隨身撕開即食，印有姓名與時段成分
• 按月冷鏈配送訂閱制（NT$ 899~1,499 / 月高黏著現金流）

Q3：評審質疑：「硬體開模成本極高且容易壓庫存，新創團隊如何承擔？」該如何漂亮回答？
回答關鍵（精實硬體與輕資產營運哲學）：

7 鎖定目標客群 Persona 定案、手機版 Web App 與看診清單價值主張

Q1：團隊最終鎖定的核心 Persona（灘頭堡客群）是誰？為什麼從電腦端擴充改為手機版 Web App？
鎖定定案 Persona｜中壯年高壓工作者（35~60 歲跨品牌自購與三高前期精算族）

手機優先的跨品牌自購與門診看診對照族

  • 典型人物代表： 陳主管／林資深專員（35~60 歲，企業中高階主管、資深工程師、金融與專業白領）。
  • 真實生活與購買情境： 台灣保健食品消費主力落在 35 歲以上，60 歲以上則多轉向單一藥袋服務。35~60 歲族群同時具備「高購買力（每人平均同時吃 5~7 罐跨品牌保健品）」與「每年公司健檢開始出現紅字／三高前期／突發門診看診」的雙重特徵，且日常 85% 以上透過手機（LINE、momo App、好市多）接收健康資訊與購物。
  • 三大致命痛點： (1) 跨品牌混吃導致維生素 E、B 群等重複超標卻完全不知情； (2) 每月花費 NT$ 2,500~4,000 卻充斥重複成分浪費； (3) 看門診、拿三高慢性藥或突發重感冒領藥時，站在診間常忘記自己家裡吃的 5~7 罐保健品確切劑量，不知道哪些該暫停或與西藥錯開。
  • 為何去除電腦擴充、改為「手機版 Web App ＋ 分享匯入」： 35~60 歲族群使用手機與 LINE 的比例遠高於電腦瀏覽器擴充功能。我們將平台打造為可加到手機主畫面的 Web App，支援從手機購物 App 一鍵分享匯入商品，並在已購買商品管理(日誌)頁面置頂「告知醫生目前使用的保健品（全螢幕大字看診卡）」，看診時一鍵出示給醫師，或一鍵分享到 LINE 讓親屬家人同步掌握家中長輩或自己的用藥清單。
  • 精準獲客與驗證管道： 政大 EMBA / 校友職場社群、LINE 職場與健康群組、PTT / Threads 職場健檢討論圈、辦公室團購。
Q2：坊間已有「每日保健藥袋／小撕包訂閱服務」，為什麼鎖定「35~60 歲跨品牌自購工作者」最具不可替代性？
鎖定客群之差異化護城河論述（回應市場替代品挑戰）：
1. 60 歲以上或單純追求便利的客群，已被坊間「每日藥袋服務」滿足： 市面上已有多家品牌提供按天分裝的每日保健小撕包服務。若消費者的核心痛點只是「不想整理瓶罐、不計較單一品牌高溢價」，直接訂購現有每日藥袋即可。

2. 35~60 歲跨品牌自購族的痛點，單一品牌藥袋永遠無法解決： 35~60 歲中壯年工作者講究「足量有效成分 × 實惠價格」，習慣跨品牌在好市多、momo 挑選各品類最強單品。單一品牌的每日藥袋存在「強制綁約與高額溢價」，更不可能幫消費者把關跨品牌重複或整理看診清單！PurePick 專攻「跨品牌去冗省錢配置 ＋ 手機版 Web App 購物分享匯入 ＋ 告知醫生目前使用的保健品（全螢幕大字看診卡）」，精準切入現有市場的絕對真空。
Q3：我們以「成分劑量與真實價格」為核心分析，針對鎖定 Persona 的核心價值主張是什麼？

我們的價值主張絕不僅止於「跟消費者站在一起（中立、不推銷）」而已，針對 35~60 歲中壯年工作者更深層的產品承諾是：

核心價值主張（Core Value Proposition）：
「隨身跨品牌保健品去冗與門診看診守護管家 —— 協助 35~60 歲工作者以最實惠的價格砍掉多餘重複瓶罐，透過手機版 Web App 隨手匯入已購保健品，在已購買商品管理(日誌)頁面隨時一鍵展開『告知醫生目前使用的保健品』大字看診卡並分享 LINE 顧及親屬，在分析頁把關待買去冗，並在日曆提供每週體感複盤與生病看診時的暫停保護。」

保健食品不是單一商品，35~60 歲族群往往同時吃 5~7 罐。如果沒有跨品牌的組合配置觀點，必然面臨重複超標與金錢浪費；如果沒有手機隨身的看診清單與動態管理，看醫生開藥時更容易產生吃錯衝突的風險。

Q4：為什麼「已購管理頁置頂告知醫生清單」加上「日曆動態管理」比傳統吃藥鬧鐘更有商業價值？

傳統用藥提醒軟體（如定時鬧鐘）用戶流失率高達 80%，因為它只有「單向打擾」。PurePick 為 35~60 歲手機使用者打造了「門診對照 ＋ 雙向動態健康閉環」：

  • 已購管理頁置頂「告知醫生目前使用的保健品（全螢幕大字看診卡）」：35~60 歲族群看診拿藥、做完健檢諮詢醫師、或陪同家中長輩看診時，不必再憑記憶背誦家裡吃哪幾罐。打開手機版 Web App 已購管理與日曆頁，第一眼就能展開「全螢幕大字看診卡」，清楚列出每一項保健品的重點成分、毫克數與「門診看診提醒（如：拔牙手術或服用抗凝血藥前請告知醫師；與抗生素或鐵劑請隔開 2 小時）」，還能一鍵透過手機分享到 LINE 給親屬家人備查，體貼長輩與照顧者。
  • 每週健康總結與 1-to-1 配方升級建議（Pro 專屬）：使用者在日曆記錄過去 7 天的體感（如「眼睛乾酸」或「下午疲倦想睡」），系統每週自動彙整痛點，主動推薦同品類吸收率或性價比更佳的進化商品，點擊一鍵加入去冗試算。
  • 生病看診／休養一鍵暫停模式：看診領取西藥（如感冒藥、抗生素、止痛藥）時，一鍵開啟「生病休養暫停」，不計入缺漏紀錄，以零摩擦方式守護就醫用藥安全。

8 未來展望：健保快易通（健康存摺 SDK）背景全自動介接與終極護城河

Q1：為什麼單純的保健品比價或去冗平台容易被抄襲？什麼是 PurePick 的不可替代性護城河？

如果 PurePick 只有「公開市售保健品比價」與「成分去冗計算」，任何資深全端工程師花兩週也能用 AI vibe-coding 做出類似工具。要建立任何競品絕對無法跨越的「結構性護城河」，核心在於掌握「使用者真實的健保西藥處方箋用藥紀錄」！

一旦掌握了民眾真實就醫開立的西藥處方，PurePick 就能做到全台灣各大電商（momo、蝦皮、iHerb）永遠不敢碰、也無法實現的殺手級功能：「西藥處方箋與保健品全自動即時交互作用攔截（Automated Drug-Nutrient Contraindication Guard）」！

Q2：衛福部健保署「健康存摺 SDK」是什麼？技術介接可行性如何？

官方開放政策背景： 衛生福利部中央健康保險署於 2019 年正式發布「全民健保健康存摺 SDK」，推動「民眾自主健康資料授權（Patient-Mediated Data Exchange）」，已成功授權智抗糖、各大型醫學中心與國泰/富邦人壽等第三方健康 App。

技術可行性評估（等級：高）：

  • 身分認證與授權架構： 採用國際標準 OAuth 2.0 與 OpenID Connect。當使用者在 PurePick 點擊「連結健保健康存摺」，系統會無縫喚起手機上的「健保快易通 App」，使用者透過生物辨識（指紋 / Face ID）或健保卡驗證後，自主同意授權給 PurePick。
  • 數據傳輸規格： RESTful API，支援國際醫療資訊交換標準 HL7 FHIR (Fast Healthcare Interoperability Resources) 與標準 JSON 格式。
  • 核心數據欄位（處方箋明細）： 包含就醫日期、醫療機構、西醫門診處方藥品（健保藥品代碼、英文藥名、ATC 解剖學治療學化學代碼、每日劑量、服用天數、適應症）。這為保健品交互作用比對提供了 100% 精確的醫學黃金數據！
Q3：介接健保健康存摺後，針對高壓白領與突發就醫有哪些殺手級應用場景？
場景一：突發感冒／抗生素自動停藥

突然就醫開立抗生素 vs 鈣/鐵/B群

白領平時不吃慢性病藥，但突然重感冒或發炎去看診拿到四環黴素等抗生素。官方 SDK 背景自動偵測就醫紀錄，立即觸發日曆「生病休養保護」或自動將鈣、鐵、綜合維他命與抗生素錯開 2~4 小時，防止金屬離子螯合導致藥效失效。

場景二：突發手術／止痛凝血阻斷

消炎止痛／抗凝血處方 vs 魚油/銀杏

若白領因外傷、拔牙手術或心血管異常突然開立高劑量 NSAIDs 消炎止痛藥或抗凝血處方，系統即時主動推播警示暫停高濃度魚油（EPA/DHA）與銀杏，降低出血與胃黏膜損傷風險。

場景三：年度健檢數值自動連動

公司健檢肝腎血脂指數反饋

健康存摺亦同步收錄抽血報告（GOT/GPT、肌酸酐、血脂、空腹血糖）。當白領做完年度公司健檢發現血脂偏高或腎絲球過濾率異常時，系統自動調整 Portfolio 推薦與安全上限警示。

Q4：為什麼目前 MVP 刻意「不做」手動匯入健保快易通，而是將其放入未來展望（Phase 2 官方 SDK）？

產品體驗與客群行為的務實取捨（Deliberate Product Decision）：

回答評審的黃金邏輯：
1. 白領不是長期吃固定西藥的慢性病患，手動匯入違反人性： 我們鎖定的高壓螢幕白領（路線一）平時身體健康，就醫多屬突發性事件（如突然重感冒、發炎、意外就醫）。若要求用戶在生病難受時，還要手動開啟健保快易通匯出檔案再上傳到網頁，操作摩擦力太高，留存率必定歸零——「靠手動的健保對接寧可不做，以免成為破壞體驗的冗餘功能」。

2. MVP 階段（現在）： 以極致零摩擦的「日曆一鍵生病休養／重感冒暫停服用模式」解決白領突發感冒時的用藥安全痛點，確保產品流程輕快流暢。

3. Phase 2（正式商轉／未來展望）： 健保署官方 SDK 開發者資格需立案公司並通過資安標章（MAS）審查（約 2~4 個月）。團隊將於成立公司後正式介接官方健康存摺 OAuth SDK，實現「完全無須用戶手動輸入，只要刷健保卡就醫，系統背景全自動偵測處方衝突並啟動保護」的終極防禦護城河！
